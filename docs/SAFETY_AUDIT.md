# MSG 0.3.7 发布前安全验收

本轮只使用 `MacSpaceGuardSelfTest` 创建的 UUID 临时目录和测试文件；没有清理用户的资源库缓存或下载文件。当前验收不等于公开发布批准。

## 已验证

| 场景 | 结果 |
| --- | --- |
| 仅扫描白名单缓存目录、只选早于截止日的普通文件 | 通过 |
| 整个 Logs 目录和白名单外路径 | 拒绝 |
| 指向白名单外的文件符号链接、符号链接缓存根目录 | 拒绝 |
| 相关应用运行中、未提供对应规则的额外确认 | 拒绝 |
| 扫描后文件修改时间或大小变化 | 跳过 |
| 扫描后被同大小、同修改时间的另一文件替换 | 通过设备号和 inode 校验并跳过 |
| 缓存清理去向 | 仅调用系统“移到废纸篓”，不直接删除或清空废纸篓；临时测试文件由模拟废纸篓接收 |
| 移到废纸篓失败 | 原文件保留，结果报告失败 |
| 安装包扫描限制在所选文件夹第一层，不跟随符号链接 | 通过 |
| 安装包文件变化或来自其他文件夹 | 不移入废纸篓 |
| 缓存清单的初始选择 | 已改为全不选；必须主动勾选或点击“全选” |
| 最终清理确认的默认按钮 | 已改为“取消” |

上述自动检查由 `swift run --disable-sandbox MacSpaceGuardSelfTest` 执行。测试使用 UUID 临时目录内的模拟废纸篓，不触碰用户真实废纸篓。缓存与安装包的“全选”只改变 UI 选择，不直接调用移动服务；此项经代码审查，尚未做独立的 GUI 自动化测试。尝试用临时文件调用系统 `FileManager.trashItem` 时，当前受限执行环境返回废纸篓访问权限错误；测试文件已清理。这不代表正式应用必然失败，也不能算通过，需在应用 GUI/正常用户环境中验收。

## 1.0 前仍需处理

1. **释放空间与恢复的取舍已明确。** 用户选择缓存和安装包统一移到废纸篓，不提供直接永久删除。移入废纸篓后仍占用磁盘空间；界面提示用户自行检查并清空废纸篓，MSG 绝不代为清空。清空后无法再通过废纸篓恢复。
2. **检查与移动之间的竞争条件。** 现在会核对设备号和 inode，同大小同时间戳的替换文件已能跳过；但最后校验与系统移到废纸篓之间仍不是原子操作。如果别的进程恰好在此时替换同一路径，仍可能移走新文件或目录。虽然可从废纸篓恢复，仍可能干扰应用。公开发布前应审查是否需要更严格的文件描述符级防护。
3. **完整测试与实机验收。** 当前机器只有 Command Line Tools，无法在此运行完整 XCTest；需要在装有 Xcode 的环境跑全套测试，并在干净的 Apple Silicon Mac 上验证首次安装、权限、菜单栏、确认与取消流程。
4. **公开分发。** 当前构建为仅支持 arm64 的临时签名版本，按用户零预算决定暂不办理 Developer ID 签名、公证。对外提供下载前需验收首次打开及系统授权流程、明确披露未经公证，并核验最终 DMG。后续可选付费签名以改善安装体验；它不能替代清理逻辑验收。

不支持 Intel Mac 是当前产品范围决定，不列为 1.0 阻塞项。
